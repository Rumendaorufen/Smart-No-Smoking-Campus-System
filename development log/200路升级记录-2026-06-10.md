# Smart No-Smoking Campus System — 200+ 路升级记录

> 日期：2026-06-10
> 基线：4 路摄像头 → 200 路目标

---

## 架构全景（升级后）

```
摄像头 RTSP (子码流) ─→ OpenCV grab/retrieve (5 FPS) ─→ YOLOv8 级联检测
                                    │
                                    ├─ 平时 2 FPS（弹性跳帧）
                                    └─ 爆发时 25 FPS（令牌桶控制）

检测结果 ─→ 两阶段置信度 ─→ 确认报警 ─→ 快照 (R:\ 内存盘 → SSD)
                                    └→ 视频 (FFmpeg → R:\ → SSD)
                                    └→ 上报 Java → WebSocket 推前端

Python 启动可选：单进程 / 多进程 Master-Workers (GPU 分片)
证据存储：ImDisk RAM 盘中转 + IOThrottle Semaphore(2) 限流
前端：网格缩略图 + el-tree 虚拟滚动 + AiChat 虚拟滚动
```

## Phase 1 — 急速救火（P0）

### 1.1 Reader 线程改造
**文件：** `stream_loader.py`, `recorder.py`

| 改动 | 说明 |
|------|------|
| `cap.read()` → `cap.grab()` + 200ms `retrieve()` | 高频清空 OpenCV 内部帧缓冲，防止老化延迟 |
| Buffer 列表 → `collections.deque(maxlen=10)` | 每帧带时间戳 `(float, Mat)`，超限自动丢弃 |
| 2.5s 超时清空 | 队首帧时间戳与当前时间差 > 2.5s → 清空，防时空错乱 |
| 证据拼接 | 录像文件开头写入 deque 历史帧（报警前 2 秒） |

### 1.2 Processor 弹性跳帧
**文件：** `detector.py`, `stream_loader.py`

| 改动 | 说明 |
|------|------|
| 平时 2 FPS | `last_process_time + 500ms` 才调一次 `detect()` |
| 爆发模式 25 FPS | 获取爆发令牌后全帧率推理 |
| `smoke_conf` 0.7 → 0.60 | 最终设定，平衡检出率与误报 |
| 两阶段置信度 | A: 单帧 ≥0.60 立即确认 / B: 同一人持续检出 3 次确认 |
| `alarm_threshold_frames` 15 → 3 | 检测频率从 25fps 降到 2fps，累计次数同步降低 |

### 1.3 全局爆发令牌桶
**文件：** `burst_token.py`（新建）

| 参数 | 值 |
|------|-----|
| 最大并发爆发数 | 3 |
| 单次爆发硬超时 | 8 秒 |
| 满员降级 | 5-10 FPS + 阈值抬至 0.85 |

### 1.4 前端瘦身
**文件：** `monitor.py`, `Monitor.vue`

| 改动 | 说明 |
|------|------|
| `/api/camera/{id}/thumbnail` | 新增 320x240 JPG 缩略图接口 |
| 单路布局 → 网格+侧边栏 | `v-mode="grid" / "detail"` 双模式 |
| 每路 `<img>` 独立定时器 | `1000 + Math.random() * 500` ms jitter 打散 HTTP 并发 |
| 侧边栏 el-tree 虚拟滚动 | `:use-virtual="true"`，200 路展开不卡顿 |
| 页面可见性自动恢复 | `visibilitychange` 监听，切回页面自动刷新 |
| 信号丢失检测 | `output_frame` 清空 + MJPEG 断开 + 缩略图离线占位 |
| 设备列表背景 | 非 scoped 样式覆盖 Element Plus 白色背景 |

## Phase 2 — 全链路降载（P1）

### 2.1 视频录制（Processor 帧 → H.264）
**文件：** `stream_loader.py`, `recorder.py`

| 改动 | 说明 |
|------|------|
| 录制源 | 利用 Processor 线程已有的帧数据，不走第二次 RTSP 连接 |
| 编码方式 | OpenCV VideoWriter `mp4v` → FFmpeg `libx264 superfast` 重编码 |
| 最终输出 | **H.264** 格式，浏览器原生可播放 |
| 视频时长 | **5s** |
| 并发录制 | 支持多路同时录像（`dict` 管理多个 VideoWriter） |
| 存储路径 | RAM 盘 → `move_to_persistent` → SSD（完成后自动迁移） |
| 移除 `_convert_to_h264` | 不再需要 mp4v → H.264 二次转码 |

### 2.2 IOThrottle 限流
**文件：** `io_throttle.py`（新建）

| 层 | 机制 |
|----|------|
| 并发限流 | `threading.Semaphore(2)`，同时最多 2 路写 SSD |
| 进程优先级 | `CREATE_BELOW_NORMAL_PRIORITY_CLASS`，不影响 MySQL |
| 超时守护 | `process.wait(timeout=30)` → `taskkill /F /T /PID` |
| FFmpeg 检测 | 启动时检测 ffmpeg 是否在 PATH，不存在则跳过录像 |

### 2.3 批量心跳 + 增量对账
**文件：** `stream_loader.py`, `DeviceController.java`, `DeviceService.java`, `device.ts`

| 组件 | 改动 |
|------|------|
| Python StreamManager | 每 3s 聚合 200 路状态批量 POST `/batch-sync` |
| 移除独立心跳 | 每路 StreamLoader 不再单独调 `_update_db_status` |
| Java 内存缓存 | `ConcurrentHashMap<Integer, DeviceState>` + `AtomicLong` 版本号 |
| 增量接口 | `GET /api/monitor/devices/delta?version=N`，无变更返回 `[]` |
| 不写 MySQL | 心跳路径只更新内存，不透写数据库 |

### 2.4 证据分级
**文件：** `stream_loader.py`

| 条件 | 行为 |
|------|------|
| 报警确认 | **无条件保存快照** (证据基石) |
| 快照存储 | RAM 盘 → `shutil.copy2` 迁移到 SSD |
| 视频录制 | **无条件录像** 5s（已确认报警即录） |

### 2.5 自动清理
**文件：** `EvidenceCleanupService.java`（新建）

| 定时 | 行为 |
|------|------|
| 每天凌晨 3 点 | 清理 7 天前未确认 / 90 天前已确认报警的视频文件 |

## Phase 3 — 架构蜕变（P2）

### 3.1 ImDisk 内存盘
**文件：** `setup_imdisk.bat`, `recorder.py`

| 组件 | 说明 |
|------|------|
| 容量 | 2GB，盘符 `R:\` |
| 写入流程 | FFmpeg / 快照 → `R:\evidence\`（纯内存）→ `move_to_persistent` → SSD |
| 无 R:\ 时 | 自动回退到 SSD，IOThrottle 依旧生效 |
| SSD 寿命保护 | 每天成千上万次的临时预录文件在 R:\ 上创建即删，不碰物理盘 |

### 3.2 多进程分片推理
**文件：** `worker_manager.py`, `worker_main.py`, `run.py`

| 组件 | 说明 |
|------|------|
| Master 进程 | Flask Web 服务 + Thumbnail + 心跳聚合，不碰 AI 推理 |
| Worker 进程 | 独立 StreamManager + SmokingDetector + GPU 绑定 |
| 分片策略 | `camera_id % total_workers` 均分 |
| 显卡绑定 | `os.environ["CUDA_VISIBLE_DEVICES"]` |
| 报警上报 | Worker `alarm_queue.put()` → Master 统一 `requests.post()` |
| **Windows 安全** | `WorkerManager` 在 `if __name__ == '__main__':` 内初始化，防递归 spawn |

### 3.3 WebSocket 增量推送
**文件：** `DeviceService.java`, `device.ts`

| 组件 | 行为 |
|------|------|
| Java 端 | `processBatchSync` 检测到变更 → `SimpMessagingTemplate` 推 `/topic/device-status` |
| 前端订阅 | SockJS + STOMP 订阅 `/topic/device-status`，增量修改 reactive 状态 |
| 重连兜底 | WebSocket 断开后自动全量 `GET /api/monitor/devices` 对账 |

### 3.4 虚拟滚动
**文件：** `AiChat.vue`

| 组件 | 替换 |
|------|------|
| 消息列表 | `el-scrollbar` + `v-for` → `<DynamicScroller>` 虚拟滚动 |
| 唯一 ID | 每条消息 `id: genMsgId()`，`msg_时间戳_自增` |

## 性能指标对比

| 指标 | 升级前 (4 路) | 升级后 (200 路) |
|------|-------------|----------------|
| GPU 推理频率 | 25 FPS 满载 | 2 FPS 常态，25 FPS 爆发 (最多 3 路) |
| 帧缓冲内存 | 60GB (理论) | < 100MB (deque maxlen=10) |
| Java QPS | ~100 req/s (每路独立心跳) | ~1 req/3s (批量聚合) |
| 磁盘 IO 模式 | mp4v + FFmpeg 转码 (2x IO) | mp4v → FFmpeg H264 + RAM 盘中转 |
| 前端并发 | 6 路 MJPEG 上限 | 200+ 路缩略图网格 (jitter 打散) |
| 证据存储 | 无条件全快照+视频 | 无条件快照+视频 + RAM 盘中转 + 自动清理 |
| 单机容量 | 4 路 (OpenCV 拉流上限) | 200 路 (grab/retrieve + 弹性跳帧) |
| 聊天页面 | 全量 DOM，消息 >50 条卡顿 | 虚拟滚动，只渲染 ~15 条 |

## 运行时参数

| 参数 | 值 | 说明 |
|------|-----|------|
| `smoke_conf` | 0.60 | YOLO 烟头检测置信度阈值 |

| `smoke_conf` | 0.50 | 最终设定，平衡检出率与误报 |

## 后期优化

### 离线检测与重连

| 改动 | 说明 |
|------|------|
| Reader 停止重试 | 连接失败/信号丢失即停止拉流，不再无限重试 |
| Watchdog 3s 超时 | 3 秒无数据自动停止线程 |
| `output_frame` 清空 | 断线时清除最后帧，`get_latest_frame` 返回 None |
| 缩略图返回 503 | 替代 1×1 GIF，前端 `@error` 触发离线显示 |
| MJPEG 断开 | 帧为 None 时断开连接，前端显示"信号丢失" |
| 前端 `isVideoError` | 网格/详情/在线计数均考虑此标志位 |
| 自动重连巡检 | StreamManager 每 30s 检查离线设备并自动重连 |
| 手动唤醒 | 用户仍可手动点击"立即唤醒"触发连接 |

### AI Agent 优化

| 改动 | 说明 |
|------|------|
| 移除 `sample_rows_in_table_info` | 节省 token 和 LLM 往返时间 |
| 恢复 `sql_db_query_checker` | 确保 SQL 语法正确性 |
| `pool_size` 2→4 | 支持更多并发查询 |

### 证据查看优化

| 改动 | 说明 |
|------|------|
| 视频加载失败回落 | 视频 404 时显示"视频不完整或不可用"+ 快照图片 |
